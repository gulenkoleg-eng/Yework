# Встановлення YEWORK на власний сервер

Встановлення складається з двох частин:

1. **Запуск програми на сервері.** Це робиться один раз через Docker або вручну.
2. **Веб-інсталятор у браузері.** Ви вводите дані бази даних, назву сайту й файлу конфігурації, обираєте тему та створюєте головного адміністратора. Після цього інсталятор назавжди вимикається.

## Вимоги до сервера

| | Мінімум | Рекомендовано |
|---|---|---|
| ОС | Linux (Ubuntu 22.04+ / Debian 12) | Ubuntu 24.04 |
| Процесор / пам'ять | 2 ядра / 2 ГБ | 4 ядра / 4 ГБ |
| Диск | 20 ГБ SSD | 50 ГБ SSD |
| Програми | Docker 24+ з Compose | — |
| Мережа | Домен, спрямований на IP сервера; відкриті порти 80 і 443 | — |

Без Docker потрібні: Node.js 22+, pnpm 10, PostgreSQL 14+ (рекомендовано 16), Redis 7 і веб-сервер з HTTPS (Caddy або Nginx).

---

## Варіант А. Docker (рекомендовано)

```bash
# 1. Отримати код
git clone https://github.com/gulenkoleg-eng/yework.git
cd yework

# 2. Налаштування
cp .env.example .env
nano .env          # змініть POSTGRES_PASSWORD і SITE_DOMAIN (напр. yework.com.ua)

# 3. Запуск
docker compose up -d --build

# 4. Ключ встановлення
docker compose logs api | grep -A2 "Ключ встановлення"
```

Відкрийте `https://ВАШ_ДОМЕН/install` і пройдіть кроки інсталятора. Сертифікат HTTPS Caddy отримає автоматично.

На кроці «База даних» для Docker вкажіть:

| Поле | Значення |
|---|---|
| Хост | `postgres` |
| Порт | `5432` |
| Назва бази | значення `POSTGRES_DB` з `.env` (за замовчуванням `yework`) |
| Користувач | значення `POSTGRES_USER` (за замовчуванням `yework`) |
| Пароль | значення `POSTGRES_PASSWORD` |

## Варіант Б. Без Docker

```bash
# PostgreSQL: створіть порожню базу й користувача
sudo -u postgres psql -c "CREATE USER yework WITH PASSWORD 'надійний-пароль';"
sudo -u postgres psql -c "CREATE DATABASE yework OWNER yework;"

# Код
git clone https://github.com/gulenkoleg-eng/yework.git && cd yework
corepack enable && pnpm install --frozen-lockfile
API_URL=http://127.0.0.1:4000 pnpm build

# Запуск (краще як служби systemd або через pm2)
cd apps/api && YEWORK_CONFIG_DIR=/var/lib/yework/config PORT=4000 node dist/main.js
cd apps/web && PORT=3000 node .next/standalone/apps/web/server.js
```

Веб-сервер має передавати `/api/*` на `127.0.0.1:4000`, а все інше на `127.0.0.1:3000` (приклад: `infra/Caddyfile`). У інсталяторі хост бази даних: `localhost`.

## Кроки веб-інсталятора

1. **Ключ встановлення.** Одноразовий код виду `ABCD-EFGH-JKLM`. Його видно в журналі API та у файлі `config/setup-key.txt`. Без нього інсталятор нічого не прийме, тож сторонній відвідувач не зможе «встановити» сайт замість вас. Тут же перевіряються вимоги до сервера.
2. **База даних.** Хост, порт, назва бази, логін і пароль. Кнопка «Перевірити підключення» пояснює помилку зрозумілою мовою: невірний пароль, бази не існує, сервер недоступний, немає прав. База має бути порожньою.
3. **Сайт.** Назва (YEWORK), слоган, адреса сайту та **назва файлу конфігурації** (наприклад `yework-prod.json`).
4. **Тема оформлення.** Одна з 6 готових тем. Встановлюються всі шість, змінити активну можна будь-коли.
5. **Головний адміністратор.** Логін, ім'я, email і/або телефон, пароль: не менше 12 символів, з великими й малими літерами та цифрою. Такий акаунт може бути лише один.
6. **Встановлення.** Створюється структура бази, права й ролі, довідник громад (Миронівська, Богуславська, Кагарлицька), теми й налаштування, записується файл конфігурації.

Після завершення:

- файл `config/<назва>.json` створено з правами `600` (читає лише власник процесу);
- створено `config/install.lock`, тож інсталятор назавжди вимкнений (відповідає 410);
- ключ встановлення видалено;
- подію «install.completed» записано в журнал аудиту.

## ⚠️ Обов'язково: резервна копія файлу конфігурації

Файл `config/<назва>.json` містить ключ шифрування персональних даних. Телефони й email користувачів у базі зашифровані. **Без цього файлу резервна копія бази марна.** Збережіть його копію поза сервером (флешка, менеджер паролів) одразу після встановлення.

## Повторне встановлення

Лише для тестового сервера: зупиніть програму, видаліть `config/install.lock` і файл конфігурації, створіть нову порожню базу, перезапустіть API. З'явиться новий ключ встановлення.

## Перевірка роботи

```bash
curl https://ВАШ_ДОМЕН/api/health        # {"ok":true,...}
```
